# PyTorch training, export and serving lab

A small, CPU-first PyTorch project that demonstrates the engineering around a
model: deterministic training, checkpointing, experiment manifests, ONNX export
with numerical validation, CPU latency benchmarking and an optional FastAPI
service. It uses a synthetic two-spirals dataset generated in-process — **no
external data, no hidden labels, no clinical claims**.

## Why this exists

The other projects in this portfolio cover NumPy-level correctness and
measurement. This one covers the deployment path: can a trained model be
reproduced, exported, checked for numerical drift, benchmarked and served?
Each claim below is backed by a committed report generated by the exact command
shown.

## Measured results (local, 2026-11-23)

Environment: Python 3.14.7, Windows 11, torch 2.15.0+cpu, 6 CPU threads.
Timings are machine-specific; re-run on your own host.

| Check | Result |
|---|---|
| Training (`python -m pytorch_lab.train --output reports`) | train accuracy 0.9975, **test accuracy 0.99**, 400 train / 100 test |
| Checkpoint | `reports/checkpoint.pt`, SHA-256 in `reports/experiment.json` |
| ONNX export + runtime validation | `passed: true`, max abs logit difference **9.54e-07**, argmax agreement 1.0 (opset 13) |
| CPU inference benchmark, batch 64, 30 repeats | median **0.0568 ms**, p95 0.088 ms, ~1.13M samples/s |

These numbers come from synthetic data and describe software behavior only.

## Layout

```
pytorch_lab/
  data.py          # seeded two-spirals generator + set_seed
  model.py         # MLP, config-driven rebuild, checkpoint loader
  train.py         # training, checkpoint, experiment manifest
  export_onnx.py   # ONNX export + onnxruntime numerical validation
  benchmark_cpu.py # warmup + median/p95 CPU latency
  serve.py         # optional FastAPI app (/health, /predict)
tests/test_training.py
reports/           # generated: experiment.json, checkpoint.pt, model.onnx,
                   # onnx_validation.json, cpu_benchmark.json
Dockerfile
```

## Commands

```bash
python -m pip install -r requirements.txt                 # torch, numpy, pytest
python -m pytest -q                                       # 8 tests
python -m pytorch_lab.train --output reports
python -m pytorch_lab.export_onnx --checkpoint reports/checkpoint.pt
python -m pytorch_lab.benchmark_cpu --checkpoint reports/checkpoint.pt

# optional serving/export stack
python -m pip install -r requirements-serving.txt
python -m pytorch_lab.serve --checkpoint reports/checkpoint.pt
```

Docker: build the image and mount a trained checkpoint at
`/app/reports/checkpoint.pt`, then `docker run -p 8000:8000 ...`.

## Defects found and fixed during verification

1. The first training run split class-ordered spirals without shuffling, giving
   **16% test accuracy** despite 99.75% train accuracy. Fixed with a seeded
   permutation before splitting; regression test asserts both classes occur in
   each partition. Retrained test accuracy: 0.99.
2. Torch 2.15's ONNX exporter requires `onnxscript` and prints non-ASCII
   progress symbols that break Windows cp1252 consoles. Added `onnxscript` to
   the optional requirements and made stdout tolerant of encoding errors.

## Limitations

- Synthetic toy data; no claim about real-world or clinical generalization.
- CPU-only benchmark; no GPU, no distributed training, no hyperparameter search.
- FastAPI/ONNX paths are optional; tests skip cleanly when dependencies are absent.
- The service is a demo endpoint, not an authenticated production service.
- Docker image was not built in this workspace (no Docker daemon available).
